先给答案：HBM 是引爆点，不是全部利润
存储厂商的盈利接近 NVIDIA，不是因为单颗 GPU 的 HBM 成本很高；而是 HBM 需求改变了稀缺资源的配置，使整个存储组合价格与经营杠杆同时向上。

传导机制
稀缺从 HBM 扩散到通用存储
AI / HBM 需求优先占用 DRAM wafer 与封装能力；供给被挤出后，服务器 DRAM、移动 / PC DRAM、NAND 和 eSSD 同时涨价。

存储厂盈利模型
全品类 ASP × 存量产能 × 高固定成本
HBM 是高价值产品，但普通 DRAM 和 NAND 在严重短缺时也能在成本变化有限的情况下捕获极高增量利润。

NVIDIA 盈利模型
高 ASP × 系统锁定 × 平台附加值
利润不仅来自 GPU；CUDA、NVLink / NVSwitch、Spectrum-X、BlueField、网络与整机交付共同构成平台定价权。

AI / HBM 需求
高层数堆叠、先进封装、认证期拉长

晶圆 / 封装被挤占
有效 bit 供给低于需求，资源稀缺扩散

存储利润池放大
DRAM、NAND、eSSD 的 ASP 与经营杠杆共振

结论：HBM 是结构性触发器；普通 DRAM、NAND 与企业级 SSD 是利润池的主要放大器。

反例验证
商品 DRAM 也能创造极高利润
Nanya 并非主流数据中心 HBM 供应商，但 Q2 2026 毛利率达 79.5%，主要由普通 DRAM ASP 上涨推动。

不可做的推导
不能从公司利润率反推产品利润率
Samsung 未披露 Memory / HBM / DRAM / NAND 独立利润；SK hynix 的 71.5% 也不是 HBM 独立营业利润率。

客户边界
终端需求不等于直接客户收入
ODM、OEM、云厂商、最终使用方和最终算力平台需区分。所有 Microsoft、Meta、Amazon、Google 与 NVIDIA 的精确客户收入归因均不可用。

阶段一：存储短缺强化

Long Memory Producers vs. Underweight Hardware OEMs
存储厂拥有提价权；PC、手机与服务器 OEM 承受 BOM 上升及需求破坏。

阶段二：ASP 上调速度见顶

Long NVIDIA / Platform vs. Underweight Commodity Memory
当合约价仍高但涨幅不再加速，存储盈利预期停止上修；NVIDIA 的采购成本压力缓解，CUDA、网络与平台租金继续留存。

07MONITORING DASHBOARD
真正需要跟踪的，不是已实现利润，而是下一季 ASP 预期差
最佳观察信号 = 实际合约 ASP 上调幅度 / 市场预期的上调幅度。即使合约价继续上涨，只要涨幅低于已计入水平，存储股仍可能见顶。

关键变量牛市确认反转信号
服务器 DRAM 合约价上调幅度不收窄连续两个季度放缓
移动 / PC DRAM涨价但需求稳定降配与出货下滑
NAND / eSSD 价格与 DRAM 同步上涨库存回升、价格转跌

NVIDIA 库存及应收与收入同步连续快于收入

库存与应收的观察方法：NVIDIA Q1 FY2027 库存由 $21.403B 增至 $25.797B，应收由 $38.466B 增至 $40.710B。当前并不自动构成需求风险；须与收入增速、供应准备共同观察。

export const buildMemorySankey = (year) => {
  const edges = sankeyEdgeRows
    .filter(([edgeYear]) => edgeYear === year)
    .map(([, source, target, value, status, confidence]) => ({ source, target, value, status, confidence }));
  const names = sankeyNodeOrder.filter((name) => edges.some((edge) => edge.source === name || edge.target === name));
  const indexByName = new Map(names.map((name, index) => [name, index]));

  return {
    nodes: names.map((name) => ({
      name,
      label: sankeyNodeLabel(name),
      stage: sankeyNodeStage(name),
      color: sankeyNodeColor(name),
    })),
    links: edges.map((edge) => ({
      ...edge,
      sourceName: edge.source,
      targetName: edge.target,
      source: indexByName.get(edge.source),
      target: indexByName.get(edge.target),
    })),
  };
};
